# Westie Radio Apps Script audit

Reviewed all four runtime source files, the README, manifest, package and lint configuration, deployment workflow, and all commits visible in the local checkout. The live Apps Script settings and Spotify account were outside this review. Use this inventory as the acceptance checklist for the Python migration.

## Feature inventory

| Current behavior | Python acceptance check |
| --- | --- |
| `Code.js` exposes `sync()` for manual runs and Apps Script time triggers. The README describes trigger setup. | Provide a manual one-shot command and run it every 15 minutes on Render. Keep test and production configurations isolated. |
| `vdj.gs` lists direct children of the configured history folder. A case-insensitive file named `disabled` exits early. | List all pages of direct, non-trashed children. The user opted out of porting the marker. |
| `vdj.gs` selects the most recently modified matching file and logs skipped names. On a tie the first listed file wins. `Code.js` exits if no file is found. | Preserve modified-time selection, including when yesterday's file wins, and use a stable tie-breaker. Require the exact date-shaped name and case-insensitive extension. Test invalid neighbors, a match on a later page, ties, and an empty folder. Log safe summary counts. |
| The parser scans `#EXTVDJ:` lines for artist and title, trims artist and title, and strips the first `(feat. …)` and `(radio edit)` case-insensitively. | Use the in-repo copy of the VirtualDJ parser for ordered media entries, positions, and metadata. Apply the legacy cleanup for search and preserve the original metadata. Test BOM, CRLF, Unicode, repeated paths and metadata, both suffixes, and incomplete metadata. Report or flag missing metadata without losing the entry's place. |
| Script Properties store the active Drive file ID and normalized artist/title keys. A file switch clears the keys. Keys are saved before search or append. | Store positions by Drive file ID in one separately configured private Drive JSON file. Test switching away and back, repeated plays, an unchanged rerun, edits before the checkpoint, and a truncated file. A new file ID has its own checkpoint. |
| `spotify.gs` uses user authorization with Spotify's OAuth2 code flow, Basic client authentication at the token endpoint, and public/private playlist write scopes. Authorization helpers display a link and handle the callback. | Document one-time user authorization and use refresh-token authentication in the scheduled process, with scopes for playlist reads and writes as needed. Verify the user can read and modify the test playlist. Keep tokens, authorization URLs, and private configuration out of logs. |
| Search uses an encoded `track:<title> artist:<artist>` query limited to one track. Adds are sent in order, one POST per match. | Verify the decoded query and first-result behavior, including spaces, ampersands, and Unicode. Preserve ordered URI occurrences regardless of request batching. On rate limits or search errors, count the failure and advance past that play. |
| `logging.gs` logs events to the Apps Script logger and a lazily created `Logs` sheet with UTC timestamps and a seven-day cleanup. `printLogEntries()` copies sheet entries to the script logger. Logs include skipped files and pairs, match failures, add/delete results, and the run summary. | Use Render run logs for operational events and confirmed counts. Document how to inspect logs and what retention the Render setup provides. Keep sensitive names, IDs, and response bodies out of operational logs. |
| A lazily created `Tracks Not Found` sheet keeps timestamp, artist, and cleaned title. The log cleanup leaves these rows in place. | Advance past a successful empty search, missing metadata, or a search failure. Track these as separate counts in Render logs. The legacy Sheets report is outside the Python scope. |
| The script fetches actual Spotify total after adds and caps the playlist at 200 by removing from the front, even if the selected file has zero new matches. | Cap the playlist at 200 entries by deleting URIs selected from the oldest entries. A deletion can also remove newer copies. Repair an oversized playlist on an otherwise unchanged run. A run with no changes and a playlist already within the cap makes zero Spotify writes. |
| The manifest configures V8, America/Chicago, exception logging, OAuth2, and a deployed web app running as the deployer. A push to `main` runs Node checks and publishes to Apps Script using clasp and GitHub secrets. | Render replaces the runtime and OAuth callback deployment. The 15-minute schedule and selection by Drive modification time need no local date boundary. The legacy Apps Script deployment workflow has been disabled in GitHub Actions. |

## Commit history and regressions

- `c3c0f01` adds the initial README and license. `6bfbdc4` adds the runtime, manifest and deployment. `e15c41c` expands the README. The subsequent migration commits are documentation only.
- `0145e6f` is the only runtime fix after the initial implementation. It replaces URI-only deletes with oldest-position targeting and uses Spotify's reported total instead of counting the URIs collected from the playlist. The diff shows that preserving later occurrences of a duplicated URI is the critical regression case. The current code omits a snapshot ID and reads only one page for each trim. The patch also introduces an undeclared `excessTrackCount`; Python should calculate a local value from the verified total.
- Test at lengths 199, 200, 201, and with overflow larger than one API page. Put the same URI on both sides of the cutoff and include multiple copies in the removal range. Verify that URI-based trimming removes all copies of selected URIs and preserves the relative order of surviving entries. Exercise missing or unavailable item payloads.
- The original script marks entries before Spotify confirms them, treats some failed searches as misses, continues after rejected adds, and reports attempted counts as successful counts. Test 401, 429, server errors, and transport timeouts separately from empty searches. Search failures count as skipped plays and advance progress. A failed earlier append must not let later entries advance past it. Persist pending appends and trims before mutation. Test process interruption after Spotify accepts each operation and before Drive confirms the final checkpoint. Resume only after a conclusive read-back and pause when concurrent edits or an unclear result prevent reconciliation.
- The old script makes multiple independent Drive and Spotify calls without a run lock. Use one Render cron job per target and test that invalid or inaccessible checkpoint state stops the run before any playlist mutation.

The local history shows code changes only. Live API behavior, live trigger configuration, and the Python acceptance checks remain to be verified during implementation and the Render test.
